# 模型思考参数适配

在设置页选择「当前模型」，展开「高级设置」，在「模型参数」中选择「思考模式」。切换模型后点击「保存」才会用于翻译。每个配置的模型独立保存模式和自定义规则；连接测试与实际翻译使用同一套请求构造逻辑。

## 已适配的 MiniMax 模型

依据 [MiniMax OpenAI Chat Completions 文档](https://platform.minimax.cn/docs/api-reference/text-chat-openai)，核对日期：2026-10-03。

| 模型 | 开启 | 关闭 | 推理强度 |
| --- | --- | --- | --- |
| `MiniMax-M3` | `thinking: {"type":"adaptive"}` | `thinking: {"type":"disabled"}` | 不支持，插件不发送该字段 |
| `MiniMax-M3.1-Flash-Preview` | `thinking: {"type":"adaptive"}` | 不支持；插件在请求前报配置错误 | `low`、`medium`、`high`、`xhigh`、`max`；自动沿用 API 默认的 `max` |

`reasoning_split` 只控制思考内容的输出格式，不能用来开关思考。Flash 不接受 `thinking.type=disabled` 或 `reasoning_effort=none`。

插件的「自动」是一项翻译策略：M3 和已有的 DeepSeek 适配默认关闭思考；Flash 保持开启。**这与 M3 的 API 默认开启行为不同。** 未识别模型不自动添加思考参数。旧设置若保存了 Flash 的关闭模式，会保留该设置供修正，界面给出原因，连接测试和翻译在发出请求前拒绝；不会悄悄改成开启，也不会自动重试这个配置错误。

思考已开启时，自动输出预算至少为 4096 tokens，避免连接测试原有的 64-token 预算完全被思考消耗。显式填写的输出上限优先。4096 是应用的预算策略，不保证模型一定能完成；复杂输入或高强度思考仍可能需要更高上限。

## 供应商还是模型

思考能力属于「接口协议下的模型」，不能只按供应商统一设开关。同一供应商的 M3 与 Flash 就有不同能力。

解析优先级是：

1. 当前配置模型的自定义规则。
2. 内置的精确模型规则（模型 ID 忽略大小写，不按 `M3*` 猜测未来型号）。
3. 供应商的兼容默认规则（目前保留已有 DeepSeek 规则及网关别名识别）。
4. 通用兼容规则：自动不传参数；显式开关使用 `thinking.type=enabled/disabled`，推理强度接受原有 `low/medium/high`。

MiniMax 的两个精确模型 ID 在其他 OpenAI 兼容网关上也能识别；若网关重写了参数协议或模型别名，请使用自定义规则。未知接口不承诺支持通用显式参数，优先使用自动或按其文档配置。

当前将用户覆盖保存在模型上，避免更改一个供应商后误伤其他型号。供应商默认值由内置适配器复用；未来出现需要用户批量配置供应商默认值的实际需求时，可在精确模型与内置供应商默认规则之间增加继承层，而不改动请求调用方。

## 无需发版的自定义

在「思考参数适配」选择「为此模型自定义」，分别填写「开启时的参数」和「关闭时的参数」。例如使用布尔开关的接口：

开启：

```json
{"enable_thinking": true}
```

关闭：

```json
{"enable_thinking": false}
```

使用推理强度控制的接口，可以按该接口文档填写：

```json
{"reasoning_effort": "high"}
```

```json
{"reasoning_effort": "none"}
```

后一种关闭方式**不适用于 MiniMax Flash**，只是其他接口的配置示例。

- 整组填 `null` 表示该动作不受支持，例如强制思考模型的关闭规则。
- `{}` 表示该动作不追加任何字段。
- 顶层字段的值为 `null` 表示删除该字段；嵌套 JSON 原样发送，嵌套的 `null` 保留。
- 请求片段按顶层字段覆盖，不进行隐式的递归合并。
- 自定义规则完全替换内置思考与推理强度映射。推理强度选择器停用，需要的强度写进 JSON。
- 自定义时的「自动」不发送开启或关闭片段，沿用上游默认值。要应用片段，请明确选择启用或禁用。
- 每组最多 4096 字符；只接受 JSON 对象或 `null`。不能覆盖模型、消息、流式控制、工具、输出格式、Token 上限和原型字段。
- 规则随模型存储、导入和导出，并参与翻译缓存标识。不要在规则内填写密钥；凭据仍使用专用 API Key / 请求头设置。
- 编辑中的无效 JSON 可以在模型间切换而不丢失，但会阻止保存和连接测试；「恢复模型默认值」清除自定义规则。

## 开发扩展位置

`extension/lib/provider/thinking.ts` 是能力和解析规则的唯一入口；新增已确认的模型通常只需添加一条声明式能力记录。`parameters.ts` 把思考结果与其他参数合成，翻译和连接测试共用它。设置界面从同一解析器取得可选动作、强度和错误原因。

`extension/lib/settings/thinking-override.ts` 负责外部 JSON 的结构验证；模型能力冲突在保存和请求边界校验，避免旧配置读取时被整套重置。自定义规则仍需符合实际上游接口文档；本地验证不能证明上游接受某个供应商字段。
