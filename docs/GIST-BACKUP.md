# Gist 备份与恢复设计

在「数据」页保留本地文件的 **导出 / 导入**，增加 **Gist** 卡片，提供连接、立即备份、恢复和历史版本。两条路径处理同一种数据快照，远端路径在上传前加密。恢复必须先预览，再由用户确认。

本稿为已实现的设计规格。策略按“手动备份、手动恢复、保留独立版本”制定；自动上传和双向同步不在本期范围。连接成功后检查备份状态，检查不写入远端、不应用远端设置。刷新或重新打开设置页需要重新输入连接凭据。

## 参考项目与取舍

研究基准：[hicms/dsh-sync-center，77b2ef8](https://github.com/hicms/dsh-sync-center/tree/77b2ef8bb453b0d117f8d6fe751fb913e798eca6)。通过 GitHub CLI 获取源码，其 `npm test` 通过。界面结论来自组件、样式和模拟渲染测试，未运行 Harness 桌面界面。

| 参考实现 | TapTranslate 采用方式 |
|---|---|
| [client.js](https://github.com/hicms/dsh-sync-center/blob/77b2ef8bb453b0d117f8d6fe751fb913e798eca6/client.js)：连接表单，状态卡，本机/云端数量，折叠差异，方向按钮，撤销和断开 | 沿用信息顺序及按状态给出动作；复用本项目 Astryx 组件与主题 |
| [lib.js](https://github.com/hicms/dsh-sync-center/blob/77b2ef8bb453b0d117f8d6fe751fb913e798eca6/lib.js)：规范化指纹、三方比较、AES-GCM 与 scrypt | 采用规范化比较和先加密原则；浏览器实现采用 Web Crypto PBKDF2，不直接复制 Node 加密代码 |
| [index.js](https://github.com/hicms/dsh-sync-center/blob/77b2ef8bb453b0d117f8d6fe751fb913e798eca6/index.js)：发现 Gist、状态/连接/同步/撤销/断开路由、写前检查 basis、动作串行 | 对应到扩展内部服务；新增快照避免共享 Gist 覆盖竞态；下载完成后才允许恢复 |
| 一个 Gist 的最新内容 + GitHub 历史 | 每次备份创建一个独立 Secret Gist，旧备份不修改；历史按备份记录展示 |
| 密码错误可用本机覆盖已有 Gist | 密码遗失时可设置新密码创建新备份；旧版本保留，需要旧密码才能恢复 |

独立 Gist 会增加账户中的条目，但上传失败或两台设备同时上传不会替换已有备份。参考项目的“读取 basis，再 PATCH”能发现已发生的变化，但读取与写入之间仍存在竞争窗口。GitHub 更新接口未提供本设计可依赖的原子比较写入契约，因此不把它描述为可靠的跨设备锁。

数量仅为线框示例。桌面保持一列内容，本机/备份两列比较；窄屏将比较改为上下两组，动作换行，弹窗可滚动。状态不能只靠颜色区分。键盘焦点、弹窗返回焦点、`aria-live` 进度和中英文文案与现有组件保持一致，其余语言使用项目的回退策略。

### 未连接

卡片内只有说明和「连接 GitHub」。点击展开表单：GitHub 令牌、创建令牌链接、备份密码、密码再次确认（创建新备份时）。令牌输入为 password，不回显已保存值。高级项只保留可选的已有 Gist 链接，用于跳过列表查找。

连接会请求 `https://api.github.com/*` 和 `https://gist.githubusercontent.com/*` 的可选主机权限，验证账户并查找本项目备份。连接成功不自动上传。已有多个备份时展示列表供选择，不取第一个就应用。不把分页到达上限解释成“没有备份”。

首次确认写清：「设置、密钥、请求头和有效翻译缓存会加密后上传到你的 GitHub 账户。请保管备份密码。」本机 JSON 导出继续使用现有明文提示。Secret Gist 的含义是未公开列出，知道链接仍能读取，所以不能用“私有”替代加密说明。[GitHub 的说明](https://docs.github.com/en/get-started/writing-on-github/editing-and-sharing-content-with-gists/creating-gists)

### 连接后的状态与动作

| 状态 | 页面文字与行为 |
|---|---|
| 会话未连接或未解锁 | 新打开设置页需重新输入令牌和密码；当前页已验证令牌时只需输入密码。历史可显示已缓存的创建时间，解锁后显示内容摘要 |
| 没有备份 | 「还没有 Gist 备份」，主按钮「立即备份」，恢复禁用 |
| 设置相同 | 「设置与所选备份一致」，单独显示缓存数量/更新时间差异；仍允许手动备份 |
| 设置不同 | 「本机与所选备份不同」，展开变化摘要；主按钮「立即备份」，次按钮「恢复」 |
| 发现其他设备的新备份 | 显示来源和时间；提示查看，不自动切换正在预览的版本 |
| 正在操作 | 显示检查/采集/加密/上传/验证/下载/解密/恢复阶段，互斥按钮禁用；没有可测比例时不显示假百分比 |
| 有未保存修改 | 与现有文件操作一致，先保存或放弃修改；云端检查可用，备份和恢复禁用 |
| 失败 | 就地显示错误及下一步，不清空已知本机摘要、不把旧状态当成最新检查成功 |
| 恢复成功 | 「已恢复，请刷新需要翻译的网页。」提供「撤销此次恢复」，注明仅当前设置页打开期间可用 |

这里的“设置相同”不表示整份备份逐字节相同。缓存增长、TTL 到期、备份时间和内部 revision 不触发设置冲突提示。折叠差异按翻译服务、目标语言与模式、站点偏好、自定义规则、内置规则快照、引导状态、权限申请清单分组；密钥和请求头值只显示“已变化”，不显示原值。

### 恢复和历史

「恢复」先完整下载所选快照并校验解密，再打开与文件导入共用的预览。预览显示来源、创建时间、扩展版本、设置与规则变化、有效/已过期缓存数量、待申请权限，以及“将替换本机已保存的数据”。默认选最近可用版本，但始终展示具体版本与设备，不把时间更新等同于内容更正确。

确认恢复时，先在点击调用链内申请权限；拒绝则零数据写入。随后复用现有恢复服务和失败补偿。当前页内存保存一份恢复前快照；成功后支持一次撤销，撤销本身也先预览并重新确认。关闭、刷新设置页或重启后撤销入口失效；历史云端备份仍可恢复。恢复后又修改了设置时，撤销预览要明确会替换这些后续修改。

历史列表每页 20 条，显示时间、设备别名、版本、大小和「预览并恢复」「在 GitHub 查看」。不自动删除旧版本；清理通过 GitHub 原生界面完成。断开只清除本机连接信息和会话密码，云端内容保留。已知但被删除的备份标为不可用，不悄悄选另一份恢复。

## 数据范围与本地存储

权威数据结构继续是 [`FullBackup`](../extension/lib/settings/backup.ts)。包含所有已保存设置、供应商配置与现有密钥、请求头、站点偏好、自定义和内置规则快照、有效缓存、引导状态、权限申请清单。缓存复用现有 `{t, at, b}` 投影，忽略本地 `epoch` 等运行元数据；不直接上传 `chrome.storage` 原始内容。

运行中翻译任务、网页 DOM、Gist 自身的令牌和备份密码不进入此快照。新设备需重新连接 GitHub；恢复不能覆盖当前连接账户。这是访问备份所需的凭据边界。权限清单用来重新申请，不意味着能导入浏览器授权本身，也不撤销导入前已有的权限。

| 数据 | 保存位置和生命周期 |
|---|---|
| 已有设置、规则、翻译缓存 | 继续由现有 storage/cache/onboarding owner 管理 |
| Gist 账户 ID、登录名、设备别名、最近选中备份、非敏感检查状态 | 独立 `chrome.storage.local` 命名空间；不进入 FullBackup 或 storage.sync |
| GitHub token、备份密码 | 默认只在当前设置页内存；页面关闭清除，重新打开需连接/解锁。首期不提供“永久记住密码” |
| 下载、解密、预览、撤销副本 | 当前设置页内存；不写日志，不塞入 storage.local/session，避免大快照耗尽配额；关闭清除 |
| 待确认上传 accountId、operationId 和对应 Gist ID | 仅非敏感本地记录，Gist ID 在响应成功后补充；只在同一账户下核对是否已经上传，换号时保留原账户待确认记录，不跨账户误认成功 |

首期选择会话凭据是为了避免引入另一套长期明文秘密存储。恢复已有的 `persistApiKey` 行为保持不变，临时供应商密钥不会因此转为持久保存。浏览器本地扩展存储也有容量限制，不能假定可额外保存一份 20 MiB 撤销包。[Chrome 存储文档](https://developer.chrome.com/docs/extensions/reference/api/storage)

## 远端格式与完整性

每次“立即备份”创建一个 `public: false` 的 Gist。通用 description 只写 TapTranslate 加密备份及随机操作标识，不写网站、模型、密钥或设备名。设备别名在密文内。每份 Gist 包含 `tap-translate.manifest.json` 和顺序命名的 `tap-translate.part-0001` 等分片，不与参考项目的 `dsh-model-sync.enc.json` 混用。

明文内容是 `{ backup: FullBackup, source: {deviceId, label}, operationId }`。20 MiB 限制仍针对 FullBackup 的 UTF-8 JSON；外层元数据和包装开销合计限制在 4 KiB 内。先序列化、加密，再把 Base64 密文按不超过 512 KiB 的 ASCII 分片拆分。最多 64 片；无需压缩或浏览器执行 git clone，不引入压缩炸弹边界。

manifest v1 包含固定 format/version、operationId、算法、KDF 参数、salt、iv、密文总字节数和有序分片清单（文件名、字节数、SHA-256）。AES-GCM 使用 256 位密钥、随机 16 字节 salt、随机 12 字节 IV、128 位认证标签；Web Crypto 返回的密文含标签。PBKDF2 使用 SHA-256 和固定 600,000 次迭代作为 v1 参数，实施时测量最低支持浏览器上的耗时；改变该协议参数需版本决策，不能随设备自行变化。密码至少 8 个 Unicode 字符，UTF-8 最多 1024 字节，不静默 trim/归一化。[Web Crypto 派生密钥接口](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey)

将 format/version/operationId/算法/KDF/salt/iv 以固定字段顺序编码为 AES-GCM additionalData。分片哈希用于及早检测传输损坏，最终以 GCM 认证判定密文完整性。解密前验证算法白名单、固定 KDF 参数、字段长度、分片个数和总大小；拒绝任意巨大迭代次数、重复编号、缺片、额外同前缀分片、未知版本或超限内容。

manifest 最大 64 KiB；密文最大为 `20 MiB + 4 KiB + 16 bytes`，Base64 上限按该数值 `4 × ceil(bytes / 3)` 计算，不能只用分片数量推算。解密后，备份 owner 再检查内层 FullBackup UTF-8 JSON 不超过 20 MiB，再做 schema 校验；当前 `parseFullBackup` 没有字节限额，必须补成文件和 Gist 都复用的有界入口，不能把外层限制误当成内层限制。

Gist API 对单文件内容可能截断；出现 `truncated` 时只读取该备份固定 revision 对应的 `raw_url`。主机必须精确为 `gist.githubusercontent.com`，路径须与所选 Gist、revision、文件名对应；不跟随任意重定向，不向 raw 主机发送 GitHub token。API token 只发到 `api.github.com`。下载按流累计字节，超过上限立即取消。[GitHub Gist API](https://docs.github.com/en/rest/gists/gists)

分片解决读取截断，不构成 GitHub 一定接受整个大请求的保证。实施时要验证请求整体大小、422/413、限流和大快照端到端行为；若平台拒绝，保持本机和旧备份不变，提示使用现有本地导出，不能静默删除缓存后称为成功。宣称 Gist 支持全部 20 MiB 范围之前，必须完成真实远端集成验证；此前只能作为明确标注该边界未验证的实验功能。如果单次请求不满足目标，需重新评审仅对新建快照分批上传并最终标记完成的协议，不能直接扩大本稿承诺。

## 操作流程和失败语义

### 连接与发现

1. 点击连接即请求可选主机权限；未授权不发送凭据。
2. 用 token 请求 `/user` 取得稳定账户 ID。创建链接预选 classic PAT 的 `gist` scope；同时接受有 Gists 写权限的 fine-grained PAT，不因缺少 `x-oauth-scopes` 头误判无权限。
3. 按账户列举 `/gists`，跟随分页，筛选 manifest 文件名；首屏限制请求页数并允许继续查找或粘贴 Gist 链接。没扫描完时显示“仍有更多结果”。读取详情检查 owner ID、format、非公开状态后才视为候选。
4. 已有链接只接受 GitHub Gist 标准 URL 或合法 ID；不用用户传入的任意 URL 发带 token 请求。候选列表按 GitHub 创建时间排序，设备信息须解密后读取。

### 上传

1. 禁止重复点击，获取本扩展来源下的数据传输互斥锁。检查未保存修改，对采集前的完整非缓存状态、生成快照的对应投影、采集后的状态计算同一个规范化指纹；三者不一致即终止并提示重试。不能只检查 settings.revision，当前 revision 不覆盖非当前服务密钥等所有变更。缓存按采集时点导出，不承诺冻结所有翻译任务；指纹复查也只提供尽力检测，不构成跨存储区事务。
2. 通过 `createFullBackup()` 生成数据并校验。比较指纹只用于摘要，用户主动备份时即使缓存变化也允许创建新版本。
3. 加密分片，持久记录随机 operationId，POST 创建新的 Secret Gist。绝不 PATCH 已有备份。
4. 得到 ID 后读取所创建的固定 revision，完整核对 manifest、分片及解密内容；只有验证通过才显示“备份成功”，更新最近备份。
5. 请求超时/关闭页面/响应丢失时标记“上传结果待确认”。重新连接后按 operationId 查找，找到完整快照即核对并收敛；找到不完整快照标记失败并给出链接，不自动删掉它。若列表未搜完，不声称上传失败或自动 POST 重试；用户可继续核对或明确创建新备份。

本机互斥锁使用扩展来源下同名 Web Lock，文件/Gist 导入导出共同接入，不承担跨设备锁职责；不支持或获取失败时明确报错，不能退回各页独立的布尔锁。不同设备同时上传各得到独立 Gist；列表同时保留。单次操作中的 Gist revision 固定，远端文件被他人编辑时不混用两个版本的分片。

### 下载与恢复

1. 绑定账户、Gist ID 和 revision 读取完整快照，解密验证后调用 `parseFullBackup`；不支持的设置版本直接拒绝，不用默认值补齐损坏数据。
2. 预览固定的该份快照，并记录本机设置指纹。确认前如果本机已保存设置变化，重新生成预览，不按旧差异执行。后台发现较新备份不替换已选版本。
3. 在确认点击中先请求权限，然后获取传输锁，再复查本机指纹。恢复守卫只比较可恢复设置、规则和引导状态，排除本次权限申请正常新增的授权；上传采集守卫仍包含权限清单。权限等待期间设置发生变化同样中止。用户关闭弹窗只取消预览，不能取消已经开始的本机写入；写入阶段提示保持页面打开。
4. 由 `restoreFullBackup` 所有者采集恢复前快照并按现有顺序应用。供预览、权限申请和执行复用的拆分也由该模块负责，不能让 Gist 服务直接写设置键或跳过校验。
5. 失败时复用现有补偿逻辑；完整补偿与补偿失败分别提示。成功后保留当前页内存中的撤销快照，重新载入设置草稿；按恢复后的实际状态重新计算比较指纹。

现有设置散布于 sync/local/session，缓存由后台持续写入，这些浏览器存储没有跨区事务。首期明确要求恢复期间停止翻译、关闭其他设置页；传输锁、指纹复查和失败补偿降低竞态，但不承诺阻止浏览器同步服务或所有其他写入方。强制关闭浏览器也可能中断恢复；保留原 Gist 和本地文件用于再次恢复。引入持久事务日志或冻结所有写入方需要另行扩展范围，不用“绝对安全”掩盖此限制。

### 错误显示

| 条件 | 行为 |
|---|---|
| 401、403、权限不足 | 区分失效令牌、权限、限流；提供重新连接，不反复自动提交 |
| 429 或限流头 | 按 Retry-After/reset 显示可重试时间；不紧密轮询 |
| 网络中断 | 读取可重试；创建结果未知时先核对 operationId |
| 错误密码或 GCM 认证失败 | 「密码不正确，或备份已损坏」，不武断区分；不写本机 |
| 高版本、非法结构、缺片、超限 | 拒绝恢复，保留已保存内容；显示可定位的错误码，不直接倾倒 Zod 数组 |
| 隐私窗口 | 禁用 Gist 上传和恢复，沿用现有缓存持久化边界 |
| 存储配额或恢复失败 | 报告是否已恢复原数据；回滚不完整须明确说明，提供原始错误码供排查 |

错误日志只记录阶段、错误码、状态码、操作标识，不记录 token、密码、Authorization、自定义请求头、翻译文本或完整备份。外部返回的 message 不能原样拼进含秘密的请求上下文。

## 模块职责和复用

本期没有独立服务器。选项页调用扩展内部业务模块，模块直连 GitHub；不复用翻译供应商的代理、API Key、URL 或自定义请求头。不增加内容脚本可调用的 Gist 消息入口。手动操作在选项页进行，关闭页面可能中断网络请求，按上述待确认状态恢复。

## 实施顺序与验收

按 Humanizer Coding 先通过计划审查，再逐步实施。以下列出验收位置；具体结果和未验证边界见 [实施验收记录](GIST-BACKUP-QA.md)。

| 顺序与所有者 | 完成条件 | 独立验证位置 |
|---|---|---|
| 1 备份模块：共用预览与恢复阶段 | 旧 JSON、本地 FullBackup、权限点击时序和 epoch 兼容保持；两来源都拒绝超过20 MiB内层数据；采集期间修改非当前服务密钥/persistApiKey等不会漏检 | 现有 `tests/full-backup.test.ts`、`tests/cache.test.ts`，新增预览测试 |
